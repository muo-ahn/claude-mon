# 도감 가중치 (C4): 미발견 배수와 최근 7일 감점

## 설계 값

| 항목 | 값 | 근거 |
|---|---|---|
| 미발견 노드 배수 | x5 (확정) | 시뮬 확정, D-7 |
| 최근 7일 출현 감점 배수 | x0.25 (확정) | 시뮬 확정, D-7 |
| 최근 창 | 오늘을 뺀 직전 7일 (KST, 나이 1~7일) | dex.json 날짜별 하루 경로 |
| 정수 척도 | DEX_WEIGHT_SCALE = 4 | x0.25 도 정수가 되게 |
| 조건 / 무조건 가중치 | 8 / 1 (변경 없음) | lib/daily.js CONDITION_EDGE_WEIGHT, UNCONDITIONAL_EDGE_WEIGHT |
| 롤백 스위치 | CLAUDEMON_DEX_WEIGHTING=0 (도감 배수 끔), CLAUDEMON_GATE_WEIGHTING=0 (기존 legacy 경로, 도감 배수도 안 붙음) | |
| dex 없음 / 비어 있음 | 배수와 척도를 전혀 곱하지 않는다 (가중치와 추첨 결과가 C4 이전과 같다) | |
| 조건 불충족 후보 | 제외 유지. 도감 배수로 되살리지 않는다 | |
| 균등 1 폴백 | 배수와 척도를 붙이지 않는다 | |

가중치 계산: `weight = max(1, round(base * DEX_WEIGHT_SCALE * mult))`. base 는 8(조건 충족) 또는 1(무조건).
미발견과 최근 출현은 동시에 성립하지 않는다 (최근 출현 노드는 발견된 노드다).

## 구현 요약

- `lib/daily.js`: `buildDexWeighting(dex, dateKST, overrides)` 가 `{ nodes, recent, undiscoveredMult, recentMult, scale }` 를 만든다. dex 가 없거나 노드가 없으면 null.
- `computeDailyTokens` 의 ctx 에 `dex` 필드를 넣는다. dex 읽기 실패는 null 로 폴백해 C4 이전 가중치로 돈다. dex 기록 (recordDex) 은 그 뒤에 그대로 둔다.
- `weightedCandidates` 가 met 후보에만 배수를 적용한다. 순방향 (candidatesFor) 과 역방향 prefix 가 같은 함수를 쓴다.
- 후보에는 `baseWeight` (8 또는 1) 를 함께 싣는다. 라우트 사유의 `candidates[].weight` 는 `baseWeight` 를 쓰므로 메뉴바의 `weight == 8` ("×8") 라벨 판정이 그대로 동작한다. `probability` 와 `totalWeight` 는 실효 가중치 기준이다. swift 는 수정하지 않았다.
- pick 의 해시 키 `${dateKST}|${rookie}|${stage}` 는 바꾸지 않았다.

## 시뮬 방법 (scripts/sim-lazy-route.js)

실제 `selectRoute`, `selectMon`, `applyDexRoute` 를 호출한다. 재구현하지 않는다.

- 하루를 단계 도달 순간마다 walk 한다. 각 단계 도달은 `selectRoute` 한 번이며, 그 시점 ctx 로 추첨하고 도달한 단계까지 고정 (lazy binding) 한다. 도달한 route 는 dex 에 접는다.
- 가정 (실사용 데이터가 아니라 고정 상수): 일 출력 토큰 로그정규 (중앙값 800k, sigma 1.0), 턴당 출력 로그정규 (중앙값 9k, sigma 0.5), 세션 수와 최다 세션 비중과 실패율은 일별 난수. 하루 안에서 sessionCount 와 dailyUserTurns 는 도달 토큰 비율에 비례해 자란다.
- 최상위 바닥 (superultimate floor) 은 실제 topTierThreshold 규칙 (직전 14일 P90, 하한 2M) 을 메모리 안의 시뮬 이력으로 계산한다. 실제 상태 디렉터리는 읽지 않는다.
- 시드 고정: 일 입력은 트라이얼마다 한 번 생성해 모든 조합이 같이 쓴다 (공통 난수). Math.random 은 조합과 트라이얼마다 같은 시드로 되돌린다. 트라이얼 40회 x 365일, 시작 날짜는 트라이얼마다 다르다.
- 지표: (a) 1위 점유율 = 하루 마지막 selectRoute 의 `superultimate` 슬롯 (터미널 채움 포함, 원문 정의에 맞춤), (b) 유효 종 수 = exp(Shannon 엔트로피) (정의 가정), (c) 후반 절반 구간, (d) 하루 끝에 실제 표시되는 최종형의 1위 점유율, (e) 최상위 도달률, (f) 트라이얼별 1위 점유율의 최소와 최대.
- 확정 규칙: 1위 점유율을 0.1%p 단위로 비교해 낮은 순, 같으면 유효 종 수 큰 순, 그래도 같으면 변화 폭 (미발견 배수 - 1 + 1 - 감점 배수) 작은 순.
- 결정성: 같은 실행 두 번의 출력이 바이트 단위로 같다 (확인함).

## 조합별 결과 (트라이얼 40, 365일, 시드 20261111)

| 조합 | 미발견 | 감점 | 1위 점유율(%) | 유효 종 수 | 후반 1위 점유율(%) | 트라이얼 1위 min-max(%) |
|---|---|---|---|---|---|---|
| 기준선 (배수 없음) | - | - | 12.2 | 41.18 | 12.1 | 7.7-15.6 |
| 미발견 x3 단독 | x3 | x1 | 11.2 | 45.20 | 11.1 | 8.8-14.8 |
| 감점 x0.5 단독 | x1 | x0.5 | 11.9 | 42.04 | 12.0 | 8.5-14.2 |
| x3 / x0.5 | x3 | x0.5 | 11.7 | 45.05 | 11.3 | 8.5-14.0 |
| x3 / x0.25 | x3 | x0.25 | 11.7 | 45.34 | 11.5 | 8.2-15.1 |
| x4 / x0.5 | x4 | x0.5 | 11.8 | 45.50 | 12.0 | 8.2-14.8 |
| x4 / x0.25 | x4 | x0.25 | 11.7 | 45.96 | 11.7 | 9.3-15.1 |
| x5 / x0.5 | x5 | x0.5 | 12.0 | 45.63 | 11.9 | 8.8-16.2 |
| **x5 / x0.25 (확정)** | **x5** | **x0.25** | **11.4** | **46.42** | **10.9** | **8.2-15.1** |

결과: 확정 조합 x5 / x0.25 의 1위 점유율은 11.4% 로 12.2% 미만이다. 기준선은 12.2% 였다.
유효 종 수는 41.2 에서 46.4 로 늘었다. 확정 조합은 점유율과 유효 종 수 두 기준 모두에서 1위다.

주의: 트라이얼별 1위 점유율의 범위가 8~15% 로 넓다. 조합 간 차이 (약 1%p) 는 트라이얼 간 분산 안에 있다. 40 트라이얼 기준 표준오차는 약 0.3%p 다. 8 트라이얼로 먼저 돌렸을 때도 x5 / x0.25 가 1위였고 (11.3%), 40 트라이얼에서 순위가 같았다. 두 번 실행 결과가 같다.

가정의 한계: 실사용 토큰과 세션 분포가 아니다. 최상위 도달률은 약 13% 다. 최상위 단계 노드는 도달 후에만 도감에 들어가므로, 최상위 단계 가중치의 효과는 다른 단계보다 약하다. 표시되는 최종형 (하루 끝 폼) 의 1위 점유율은 4.1% 로 작다. 이는 하루 끝 폼이 여러 종으로 흩어져 있다는 뜻이며, 원문 12.2% 는 최상위 슬롯 기준이다.

## 확정 수치 보고

- D-7 확정: 미발견 x5, 최근 7일 감점 x0.25 (기본 x3 / x0.5 에서 변경).
- 시뮬 기준 1위 점유율 12.2% -> 11.4% (12.2% 미만). G2 의 12.2% 판정은 C5 (덱 확장) 통합 후 통합 브랜치에서 다시 잰다.
- 메뉴바 Swift 는 변경하지 않았다.
