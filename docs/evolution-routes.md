# 진화 루트(랜덤 진화) 요구사항

2026-07-30 정리. `lib/daily.js`의 `selectRoute`와 `sprites/packs/*/pack.json`의 `tree`가
대상이다. 구현된 부분과 아직 아닌 부분을 분리해 적었다.

## 1. 왜 고치는가

첫 구현(커밋 `2e52e20`)은 단계별로 후보를 뽑고, 후속이 없는 분기를 만나면 **다음 단계의
spine으로 되돌아왔다**(spine 복귀). 이게 그래프에 없는 엣지를 코드가 만들어내는 짓이었다:

- `라이즈그레이몬 → 워그레이몬` — 실제 후속은 샤인그레이몬이고, 워그레이몬은 메탈그레이몬
  계보다. 서로 다른 두 계보를 이어붙였다.
- `블랙메가로그라우몬 → 듀크몬`, `매그너몬 → 황제드라몬 파이터 모드` — 같은 방식의 가짜 엣지.

결과적으로 "성숙기에서 갈라지면 이후 진화체도 제약된다"는 디지몬 진화의 기본 성질이 깨졌다.
표기상 14개였던 하루 루트 중 절반이 이렇게 만들어진 것이었다.

별개로, 게임 표에는 있지만 계보 감각과 어긋나는 엣지도 있다:

- `워가루몬 → 다크드라몬` (DWDS 표에 존재). 통상은 **블랙워가루몬 → 다크드라몬**이다.
- `인퍼몬 → 베르제브몬` (DWDS 표에 존재). 캐논상 베르제브몬은 임프몬 계보다.

## 2. 설계 원칙

- **인접리스트가 유일한 진실.** 노드의 `next`에 없는 전이는 존재하지 않는다. 폴백으로
  전이를 합성하지 않는다.
- **크기에 맞는 도구.** 전체 그래프는 노드 수십 개 규모다. graph DB·전용 엔진은 과잉이며,
  `pack.json`의 인접리스트 + 20줄 DAG 워크로 충분하다.
- **부분 완성이 정상 상태.** 트리는 매주 조금씩 채워진다. 반쯤 만든 분기가 그날의 추첨을
  깨뜨리지 않아야 한다.
- **없는 데이터를 그럴듯하게 만들지 않는다.** 도트가 없으면 그 분기는 쓰지 않는다. 지표가
  일 단위가 아니면 그렇다고 적는다.

## 3. 데이터 모델 (`evolution-graph.json`)

전역 진화 그래프. 노드 배열 하나에 전 계보가 들어 있다.

```jsonc
{
  "version": "1.0.0",
  "generatedBy": "scripts/migrate-packs-to-graph.js",
  "nodes": [
    {
      "id": "greymon",          // 전역 유일
      "name": "그레이몬",        // 표시 이름 (한글명 규칙은 §7)
      "stage": "adult",         // 어느 칸인지
      "sprite": "greymon",      // 도트 파일 prefix: sprites/nodes/<sprite>-0.png
      "evolvesFrom": [          // 부모 목록. 관계를 자식이 소유한다
        { "from": "geogreymon", "when": null }
      ]
    }
  ]
}
```

- 각 스테이지 배열의 **첫 노드가 spine**이다. 트리가 없는 팩은 `stageNames`로 동작한다(호환).
- `sprite`가 spine이면 관례적으로 스테이지 id와 같다(`adult-0.png`). 분기는
  `adult-geogreymon-0.png`처럼 `<stage>-<id>` 규칙을 쓴다.
- 도트 파일은 커밋되지 않는다. 따라서 **트리에 이름이 있어도 도트가 없을 수 있다**는 것이
  정상이며, 선택 로직이 이를 걸러야 한다(R2).

최상위부터 내려오며 "도달 가능 = 도트 있음 AND (최상위이거나 도달 가능한 후속이 하나 이상)").

> 상태 열은 2026-07-30 기준이다. 2026-08-05 조건부 진화 전환(`evolutions[].when`) 이후
> R1은 구현 완료됐고, R2/R6의 도달 보장은 런타임 도달 가능성 계산 대신 **"비최상위 노드의
> 마지막 엣지 = `when: null`" 데이터 계약 + `validatePackTree`**로 대체됐다(README §랜덤
> 진화). R9는 2026-08-07 명문화(TODOS 1번). **2026-08-19 D7 이후 R2/R6은 다시 완화됐다** —
> "최상위 스테이지까지 엣지가 이어짐"이 "최상위까지 이어지거나 종점에서 끝남"으로 바뀌었다.
> 도달 보장 자체는 유지된다(종점도 "도달"로 친다), 다만 도달 대상이 전역 최상위 한 곳에서
> 라인별 종점으로 넓어졌다. **2026-08-20 Phase B 전환에서** 도달 보장은 폴백("조건 맞는 후보
> 없으면 전체 후보")에서 나오고, 종점은 `terminal: true` 플래그가 아니라 역인덱스 `childrenOf`
> 에서 파생된다("다음 칸에서 나를 부모로 지목한 노드가 없음"). `validatePackTree` →
> `validateGraph` 대체(`docs/global-graph-plan.md` §B-1·§B-3).

## 5. 성장 배경(trait) — 현재값과 한계

| trait | 조건 | 데이터 출처 | 한계 |
|---|---|---|---|
| `dark` | 도구 호출 실패율 ≥ 5% | `global.json` 누적 카운터 | **일 단위가 아님.** 일일 실패 카운터를 `hook.js`에 추가해야 해결 |

## 6. 점진적 채우기 (주 ~15노드)

R2가 있으면 다음 순서로 아무 때나 노드를 추가할 수 있다.

1. DWDS 시트를 `sprites/sheets/dwds/<name>.png`로 넣는다.
2. `python3 scripts/extract_pack_evolved_dwds.py --contact <name> /tmp/x.png` → 정면 걷기
   프레임 2개를 눈으로 고른다.
3. `PICKS`에 한 줄(`"<stage>-<id>": ("<sheet>", [i, j])`), `pack.json` `tree`에 노드 하나.
4. 추출 → `node --test`.

노드당 1~2분이며 병목은 프레임 고르기다. **최상위까지의 사슬을 완성시키는 노드를 우선**한다
(한 노드가 루트 하나를 즉시 늘린다). 사슬 중간 노드만 늘리면 R2 때문에 아직 추첨에 들어오지
않는다 — 의도된 동작이다.

### 필요한 도구

| 도구 | 목적 | 상태 |
|---|---|---|
| `--contact <sheet>` | 감지된 필드 프레임을 번호 붙여 한 줄로 렌더 | ✅ 있음 |
| 트리 lint 테스트 | `next` id 존재, 스테이지 순서 위반·순환 없음, spine 존재 | ❌ 신규 |
| `scripts/tree-status.js` | 도트 없는 노드 / 후속 없는 노드 / 추첨 제외 사유 / 필요한 시트 목록 | ❌ 신규 |

### 10.1 수배 등록 게이트 (2026-08-10)

수배(다음 편입 후보 공지)는 개체가 아니라 **막힌 엣지** 단위로 등록한다. "성숙기에서
갈라지면 후속도 갈린다"(§2, D1)는 계보 제약 때문에 개체 하나만 지목하면 그 개체의
상위·하위 계보 정합성을 확인할 길이 없다. 등록 전 다음을 모두 확인한다.

ⓐ Wikimon 문서 URL을 확보한다.
ⓑ 그 문서의 **"Evolves From" 표**(자식 페이지 한 곳)에 **DWDS(Dawn/Dusk, 보유 397) 또는 확보 예정
로스터(Digimon World DS / Lost Evolution / Super Xros Wars, ROM 립 대상)** 태그가
실제로 붙어 있는지 확인한다. `evolvesFrom` 모델에서 게이트 판정이 자식 페이지에서 끝난다(§B-1·§B-6).
ⓒ 편입 시 **그 부모의 파생 fan-out**(다음 칸에서 그 노드를 부모로 지목한 노드 수)을 계산하고,
어느 조건 축으로 가를 것인지 결정한다. **무조건 엣지(`when: null`)를 늘리는 것은 분기점을
늘리는 게 아니라 제비뽑기를 늘리는 것**이다 — 알(digitama)이 증거다: fan-out 10인데 조건
0개라 순수 날짜 해시다. **하류 분기의 조건 축이 같은 라인 상류 분기의 축과 같으면 하류 분기가
도달 불가가 될 수 있다** (조건 참 시 상류에서 다른 갈래로 새어 하류 노드 우회, 거짓 시 하류
조건 미충족). 그래서 편입 시 **조건 충족·미충족 여러 상태로 실제 `selectRoute`를 28일 ×
조건 조합 전수로 돌려 새 노드가 route에 등장하는지 확인**해야 한다. **fan-out을 세는 것
(데이터 구조의 성질)은 도달 가능성 확인이 아니다** — `childrenOf.get().length`는 2여도
실제 route에는 한 경로만 나타날 수 있다. `validateGraph`도 이것을 잡지 못한다 — 그래프
구조는 정상이고 도달 가능성만 죽는다. **실측 사례 (`weregarurumon → darkdramon`, 2026-08-20)**:
초안 `failureRatioPct >= 5`는 상류 `garurumon → blackweregarurumon` (`>= 5`)과 축 충돌.
28일 × 실패율 {0,3,5,10}% = 112 조합 전수에서 `weregarurumon → darkdramon` **0회 등장**
(실패율 ≥5 → 상류가 blackweregarurumon으로 새어 weregarurumon 우회, <5 → darkdramon
조건 미충족). `sessionCount >= 3`으로 수정 후 28일 × {2,3,5} = 84 조합 전수에서
`weregarurumon → darkdramon` 56회 + `weregarurumon → metalgarurumon` 28회 — 두 경로
모두 도달 가능 확인. 누적 축(`failureRatioPct` 등)은 실사용 데이터에서 아예 안 움직일 수
있다 (2026-08-20 실측 `toolFailureCount: 0` = 영원히 0%). **축의 의미와 도달 가능성이
충돌하면 도달 가능성이 이긴다** — 의미가 맞아도 도달할 수 없으면 값이 0이다.

**조건 축 부하 (2026-08-20 실측)**: 하루 안에서 의미 있게 움직이는 조건 축은 5개다
(`dailyOutputTokens` · `sessionCount` · `topSharePct` · `dailyUserTurns` · `outputPerTurn`.
`failureRatioPct` · `globalToolSuccessCount` · `consecutiveDaysActive`는 누적값이라 하루
안에서 안 움직인다). 현재 최대 fan-out은 digitama 10이고(조건 0개), 그 다음이 브이몬 3
(`sessionCount`·`topSharePct`·무조건 각 1). fan-out이 축보다 많아지면 타이브레이크가
`hashString(날짜|팩|단계)` = 제비뽑기로 떨어져 §0 목표("모든 진화 분기가 그 순간의
조건으로 결정")와 정면으로 어긋난다. 재검 트리거는 **한 노드의 fan-out ≥ 4**다
(`docs/global-graph-plan.md` §7).

ⓐⓑⓒ 중 하나라도 없으면 등록을 금지한다. 게이트 없이 자동 생성된 과거 수배 3건 중
