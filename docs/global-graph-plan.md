# 계획: 전역 진화 그래프 + 지연 진화 (Phase B → Phase A)

작성 2026-08-19. 선행 완료: D7(#23, `81a3f5f`). `docs/evolution-routes.md`와 짝을 이루는
문서다 — 그쪽은 팩 단위 랜덤 진화의 현재 계약을, 이 문서는 팩 경계를 없애는 다음 단계를 다룬다.

## 0. 목표

**알 하나에서 시작해, 모든 진화 분기가 그 순간의 조건으로 결정되는 단일 그래프.**
팩은 계보의 소유자가 아니라 표시 뷰로 축소된다.

```
digitama ─[조건]→ 유년기 ─[조건]→ 성장기 ─[조건]→ … ─[조건]→ 종점 또는 초궁극체
```

## 1. 왜 — 지금 무엇이 막고 있나

`pack.json` 하나가 세 관심사를 겸하고 있다.

```
pack.json ─┬─ 계보 그래프      (tree: 노드 + 조건 엣지)
           ├─ 표시 이름        (name, stageNames)
           └─ 도트 파일 소유   (sprite prefix → <pack>/<prefix>-N.png)
```

세 번째가 첫 번째를 인질로 잡는다. 렌더러가 자산을 `<팩 디렉터리>/<prefix>-N.png`
(초상은 `portrait-<prefix>-N.png`)로 찾으므로 노드는 팩 디렉터리에 물리적으로 속해야 하고,
그래서 그래프도 팩 안에 갇힌다. 결과:

- 같은 개체가 팩마다 별개 노드로 복제된다 — 오메가몬(아구몬·파피몬), 베르제브몬(임프몬·케라몬).
  베르제브몬은 sprite prefix까지 갈라져 있다(`ultimate` vs `ultimate-beelzebumon`).
- 라인 교차가 불가능하다. `id`는 "팩 안에서 유일", 엣지 `to`는 "같은 팩의 노드"가
  문서화된 계약이고(`docs/evolution-routes.md` §3), `validatePackTree`의 `unknown-target`이
  팩 밖 참조를 거부한다.
- **로키가 조건이 아니라 제비뽑기로 결정된다.** `selectMon`이 날짜 해시 셔플 덱으로 오늘의
  팩을 먼저 고르므로 `digitama → 유년기 → 성장기` 세 칸에는 조건 판단이 아예 없다.
- 도달하지 않은 칸이 `route`에 미리 채워져 밖에서 보면 미래가 확정된 것처럼 보인다.

## 2. 선행 조건

- **Q1 결론 필수** (`docs/evolution-routes.md` §9) — `인퍼몬 → 베르제브몬`은 DWDS 표에는
  있으나 캐논상 임프몬 계보다. 지금은 그 의심 엣지가 케라몬 팩 안에 **격리**돼 있는데,
  병합하면 격리가 사라져 임프몬 라인 전체가 아마게몬에 닿게 된다. 병합 전에 결론내야 한다.
- **D3 보류 사유 소멸 (완료)** — D3("지연 진화는 D2와 상충")의 근거였던 D2를 D7이 완화했다.
  도달 전에 경로 전체가 확정돼 있어야 할 이유가 없어졌다.

## 3. Phase B — 그래프와 자산을 분리한다

### B-1 데이터 구조

```
evolution-graph.json          전역 노드 + 엣지 (단일 진실)
sprites/nodes/<id>-{0,1}.png  노드 단위 도트
sprites/nodes/portrait-<id>-*.png
sprites/packs/<rookie>.json   뷰 — 시작 노드 + 표시 이름 (tree 제거)
```

노드는 `{ id, name, stage, terminal? }`, 엣지는 소유 노드의 `evolutions: [{ to, when }]`을
유지한다(인접리스트 형태 보존 — 조건 엔진과 검증기가 그대로 재사용된다).

### B-2 런타임 호환 — 이것이 설계를 결정한다

`route`에 실리는 값은 **계속 전부 문자열**이고 `sprite`는 **팩-상대 prefix**로 내보낸다.
그러면 메뉴바는 지금처럼 `<현재팩>/<prefix>-N.png`를 읽어 **무변경**이고, 사용자가 손빌드해
상주시키는 **구형 바이너리도 무손상**이다.

- `scripts/materialize-sprites.js` 신설 — `sprites/nodes/`를 각 팩이 필요한 노드에 맞춰
  팩 디렉터리로 복사(또는 하드링크)한다. 도트는 gitignore 대상이라 물리 중복은 무비용이고,
  이 저장소가 이미 쓰는 파생물 패턴이다(맵 HTML, 추출 스크립트).
- 대안 (a) "Swift를 `sprites/nodes/`를 직접 읽게 바꾼다"는 **B 이후 별도 결정**으로 미룬다.
  깨끗하지만 D7에서 겪은 롤아웃 창이 다시 열린다(구형 바이너리가 파일을 못 찾아 한 단계
  아래 프레임으로 폴백 → "진화했는데 퇴화"로 보인다).

### B-3 코드 변경

| 대상 | 변경 |
|---|---|
| `readTree` → `readGraph` | 팩별 로드 → 전역 1회 로드. `byId` 전역 |
| `validatePackTree` → `validateGraph` | 시그니처가 "단일 팩 트리"에서 전역 그래프로. `unknown-target`·`stage-skip`·`terminal-with-edges`·`missing-terminal` 규칙은 유지하고 팩 경계만 제거 |
| 신규 규칙 | **순환 검출** — 전역이 되면 사이클이 표현 가능해진다. 지금은 팩별 스테이지 계층이 구조적으로 막아줬다 |
| `selectRoute` | 팩 대신 **로키 노드**에서 시작 |
| `listRotationPacks` | B에서는 로키 목록으로 유지 (A에서 제거) |
| `scripts/build-evolution-map.js` | 팩별 열 → 단일 그래프. 공유 노드 1회 렌더. `orphanNodes`·`offCatalog` 진단이 전역 기준이 되어 유용해진다 |

### B-4 B만으로 즉시 얻는 것 — 도트 0장

중복 노드를 합치는 것만으로 경로가 **26 → 28**로 늘어난다.

```
현재                                    B 이후
뱀파이몬 → 베르제브몬 → 블래스트 모드      뱀파이몬 ─┐            ┌→ 블래스트 모드
인펠몬   → 베르제브몬 → 아마게몬                     ├→ 베르제브몬 ┤
        (같은 개체, 별개 노드)            인펠몬   ─┘            └→ 아마게몬
```

임프몬 라인이 아마게몬에, 케라몬 라인이 블래스트 모드에 닿는다. (Q1 결론에 종속 — §2)

그리고 이후 모든 편입의 단가가 내려간다. 티라노몬을 한 번 넣으면 아구몬·길몬 양쪽에서
엣지 한 줄로 재사용된다. 지금은 두 팩에 노드와 도트를 각각 넣어야 한다.

### B-5 병합 실측 (2026-08-19)

```
팩별 노드 엔트리 90  →  전역 고유 노드 79  (11개 중복 소멸)
루트(in-degree 0)  1  ← digitama. 10팩의 알이 하나로 합쳐진다
엣지(고유)         90
수렴 노드(in-deg≥2) 9  메탈그레이몬·오메가몬·베르제브몬·아마게몬·듀크몬 크림슨·
                       파일드라몬·황제드라몬 PM·블랙래피드몬·세인트가르고몬
종점(out-deg 0)   12
```

정사상 조그레스(합체)라 "각자 독립적으로 도달"은 여전히 의미가 틀리지만, 전역 그래프가
되면 표현을 얹을 자리가 생긴다(§7).

## 4. Phase A — 지연 진화를 완성한다

성장기 위 구간은 **이미** 진화 직전 판단이다. `walk`이 30초마다 재계산하고 도달한 칸만
핀되므로, 잠기는 값은 그 순간의 지표로 판단된 값이다(테스트
`selectRoute locks the reached stage against condition changes but leaves the rest open`).
남은 것은 두 개뿐이다.

### A-1 로키를 조건으로 결정한다

`selectMon` 폐기. `digitama`의 출구 엣지에 `when`을 단다 — **B가 선행조건인 이유가 이것이다.**
알 밑에 10갈래가 모여 있지 않으면 조건을 걸 자리가 없다.

**결정 시점 문제**: 성장기는 output 30K에서 잠긴다(유년기는 1토큰). 그 시점에 오늘을 판별할
지표가 거의 없다 — 세션 수·집중도·턴당 출력은 모두 하루가 지나야 의미가 생긴다. 이것이
애초에 로키가 날짜 해시였던 이유다.

→ **초반 엣지는 누적·어제 지표로 판단한다.** 회피가 아니라 "성장 배경"의 정의 그대로다.
신규 조건 타입 후보: `yesterdaySessionCount`, `yesterdayTopSharePct`,
`recentFailureRatioPct`(N일 창), 기존 `consecutiveDaysActive`·`milestone`.

**잃는 것**: 셔플 덱 로테이션과 `mon-history.json`이 존재 이유를 잃는다(`81a3f5f`에 방금
들어간 작업이다). 로키가 지표로 결정되면 "고르게 등장"은 목표가 아니고, 지표가 편향돼
있으면 특정 로키가 계속 나오는 것이 **정상**이 된다. 이 교환을 받아들이는 것이 A-1의 실질이다.

### A-2 미확정 구간을 비운다

`route`에 도달한 칸까지만 기록한다. `daily.json`이 하루에 걸쳐 자란다.

- 메뉴바는 route 변경 시 프레임을 다시 읽으므로 커지는 route를 견딘다. `applyRoute` 캐시
  키에 name이 포함된 것은 #23에서 이미 들어갔다.
- 맵의 "오늘의 루트"가 **걸어온 경로 + 가능한 미래**로 바뀐다.

### A-3 멱등성 포기를 명문화한다

지금은 날짜+지표로 언제든 재계산 가능하다. 완전 지연 평가는 "그 순간의 값"에 의존하므로
`daily.json`을 지우면 복원할 수 없다. lazy binding이 이미 부분적으로 그렇지만(핀된 접두부),
전면화하면 완전히 상태 의존이 된다. `Math.random` 금지는 유지한다 — 같은 `daily.json` +
같은 지표면 같은 결과여야 한다.

## 7. 열린 질문

- **Q1** (§2) — 병합 전 결론 필수
- **조건 축 상한** — 하루 단위로 의미 있는 조건 축은 5개다(`dailyOutputTokens`,
  `sessionCount`, `topSharePct`, `dailyUserTurns`, `outputPerTurn`. `failureRatioPct`·
  `globalToolSuccessCount`·`consecutiveDaysActive`는 누적값이라 하루 안에서 안 움직인다).
  한 노드의 갈래가 축보다 많아지면 날짜 해시 타이브레이크로 떨어져 **다시 제비뽑기가 된다.**
  현재 최대 fan-out은 2라 여유가 있다. **트리거는 날짜가 아니라 fan-out ≥ 4** —
  공교롭게도 "아구몬 6갈래"를 실현하려는 순간이 정확히 그 지점이다. 충분한 확장 이후 재검.
- **조그레스** — 전역 그래프면 `parents: [워그레이몬, 메탈가루몬]` 같은 표현을 얹을 자리가
  생기지만, claudemon은 하루에 마스코트가 1마리라 **발동 조건이 존재하지 않는다.**
- **Swift를 노드 경로로 전환할지** — B-2의 대안 (a). B 이후 롤아웃 창 감수 여부로 별도 결정.
